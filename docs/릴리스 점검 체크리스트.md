# 쉐어드 릴리스 점검 체크리스트

태그를 달기 전에 아래를 위에서부터 확인한다. push·태그는 개발자 승인 뒤에만 한다. (새 스크립트 없이 이 문서 하나로 관리한다.)

1. **버전 일치**: `package.json` 의 `version` 이 달려는 태그 이름과 같다(예: 태그 `v0.4.0-rc.11` ↔ `"version": "0.4.0-rc.11"`). 이미 push 된 태그는 옮기지 않는다(앱이 태그로 고정한다). 어긋났으면 다음 번호로 올려 바로잡고 CHANGELOG 에 «표기 정정» 한 줄을 남긴다.
2. **CHANGELOG**: 맨 위 절 제목이 같은 태그 이름이고 «Unreleased» 절이 남아 있지 않다. 추가형인지(기존 이름·시그니처·반환형·기본 동작 불변), 동작이 바뀌는 곳(기본값 신설 등)은 «동작 변경» 으로 적었는지 확인한다.
3. **시험**: `npx vitest run --root .`(Git Bash 는 `--root .` 필수, PowerShell 은 `npm test`) 전체 통과, `npx tsc --noEmit` 오류 없음. 토스 통합 시험(`npm run test:toss`)은 평소 제외.
4. **계약 호환**: `src/rc11-compat.test.ts` 처럼 앱이 쓰는 공개 이름이 그대로 있는지 확인하고, 새 공개 이름을 `package.json` `exports` 에 추가했으면 서브패스가 열려 있는지 본다.
5. **미추적 설계서·작업 폴더 제외**: `git status` 에서 커밋 대상이 의도한 파일뿐이다(`.claude/` 는 `.gitignore`).
6. **승인 뒤 순서**: main 병합 → 태그 → push. 소비 앱(미트·이음·레저코어)의 핀 올리기는 태그 뒤 각 담당이 한다.
